# iOS 图片记账（相册与快捷指令）

完整实施需求见 [Codex 提示词](ios-screenshot-bookkeeping-prompt.md)。

## 从相册记账

在“财务 → 右上角菜单 → 图片记账”选择视觉 AI 并同意图片外发，然后点击“从相册选择图片”。系统照片选择器只读取你选中的单张图片，不申请整个相册的读取权限。选中后自动压缩、校验并交给 AI；信息完整且账户尾号唯一匹配时记账，否则在处理记录中核对。取消选图不会上传；每次选图均创建新任务并重新分析，包括之前已忽略或已入账的同一图片。iCloud 图片读取失败或 AI 失败会显示错误，已经创建的任务保留供重试。

相册入口无需创建快捷指令或设置轻点背面。当前识别范围是任意来源的单笔人民币支付图片，渠道缺失不阻止入账，不扩展到普通照片或多笔账单。

## 快捷指令使用方式

1. 部署包含 `POST /api/ai/screenshot` 的后端，安装本次 iOS 构建。此实现没有自动部署，也没有使用真实截图测试上游。
2. 在“我的”登录并开启同步，添加一个支持图片输入的 Chat Completions 兼容 AI 配置。
3. 打开“财务 → 右上角菜单 → 图片记账”，选择视觉 AI，阅读接收服务地址、提供商与模型，点击“同意外发并启用”。换配置先停用，再重新同意；远端配置版本变化也会拒绝旧同意。
6. 在“设置轻点背面”点击“添加图片记账快捷指令”，用系统快捷指令打开并确认添加。应用附带已通过 Apple 签名的 `Resources/图片记账.shortcut`，包含 **截屏 → 个人助理：识别截图并记账**，图片参数已绑定截屏输出，无需手动搭建。已有同名快捷指令可选择替换。
7. 在 **设置 → 辅助功能 → 触控 → 轻点背面 → 轻点两下** 选择已添加的“图片记账”快捷指令。
8. 在任意来源的单笔交易成功页或详情页轻点两下。系统先截屏，个人助理后台分析并在校验通过时自动入账，保留当前页面。快捷指令中无需“打开个人助理”或“显示结果”动作。

系统添加确认、图片权限首次确认和背面轻点绑定由用户操作。应用提供已签名文件；没有 iCloud 分享链接，也不能静默修改系统设置。Apple 官方说明：[轻点背面运行操作和快捷指令](https://support.apple.com/en-lb/guide/iphone/iphaa57e7885/ios)、[App Intent 执行模式](https://developer.apple.com/documentation/appintents/configuring-the-runtime-behavior-of-your-app-intents)。

快捷指令源码位于 `apps/iOS/PersonalAssistant/Shortcuts/ScreenshotBookkeeping.plist`。App Intent 标识、团队或参数变化后须重新使用 `shortcuts sign --mode anyone` 签名。签名通过不代表真机导入、分享菜单打开方式、同名替换后保留背面绑定和实际截图记账已验证。

## 当前行为

- **钱包卡面**：iOS 信用账户编辑中的卡片改为钱包堆叠，点选展开名称、卡号和更换卡面。名称稳定后使用银行名与卡种名自动查找，搜索词移除连续数字，不发送卡号或账务信息。优先查找已验证的招商银行官方产品页，其余使用公开图片搜索；只在来源银行和卡种匹配时自动采用。外部网页结构或素材变化可能导致无结果，保留品牌色卡面。
- **卡面缓存**：可手动选候选或从相册选择；手选后不被自动匹配覆盖。图片去除元数据后按用户空间和卡片保存在本机缓存，不参与财务同步。更换卡片名称会淘汰旧的自动匹配缓存；手选不受影响。测试入口为 `--preview --wallet-ui`，虚构资料且禁用自动联网；`CardArtworkTests --live` 可独立验证公开官方页面。

- **共用账单多卡**：信用账户编辑页通过“账单下的卡片”维护名称与卡号，最多 30 张；支持完整卡号或四位尾号，保存时脱敏。旧单卡字段在编辑保存时迁移。卡片没有独立余额、额度、账单日或还款日；消费和还款沿用所属账户，资产负债只统计账户一次。
- **多卡识别**：任一下属卡尾号命中唯一可用账户即可归入该账户，同一账户多张卡同尾号不会重复计算账户，不同账户同尾号仍需确认。截图流水备注保留原商品或订单描述及其中的平台来源，不拼入卡片名称及尾号；尾号仍用于账户匹配。人民币金额必须来自识别证据，不自行估算外币汇率。
- **同步协议**：账户新增可选 `cards` 数组（`id`、`name`、`maskedAccountNumber`）；服务端自动迁移 JSON 存储列，PATCH 仅更新提交字段，`cards: []` 清空卡片。上线需同步更新后端和 iOS；旧版后端会拒绝新字段。

- **卡尾号匹配**：AI 从实际付款方式区域提取 `paymentCardLast4`，iOS 在本机按账户 `maskedAccountNumber` 匹配唯一可用人民币账户，账户编辑页可填写卡号后四位。同尾号多个可用账户、未匹配或没有尾号时待确认。账户目录不发送给 AI。旧识别结果没有新字段时仍可读取。
- **英文截图**：提示词要求付款方式、分类、原因使用简体中文；商户有明确中文名时翻译，不确定的品牌专名保留原名。金额及支付证据保留原文，订单号和协议字段不翻译。支持任意来源的人民币支出，支付渠道可未知；英文不等于外币。中文翻译质量需真实模型截图验证。

- **范围**：微信、支付宝已支付人民币支出，包含单笔成功页和详情页。收入、退款、转账、还款、充值、外币、无法确定状态和多笔页面不自动入账；不支持的结果可忽略。
- **自动入账**：只校验实际记账所需的合法金额、交易日期及可用扣款账户。订单号、证据原文、备注、商户和时分不是入账门槛，AI 的 `needsReview` 或“未显示完整交易单号”不单独阻止入账。分类能匹配时采用，匹配不到时可为空；不会创建额外“默认”分类。实付金额直接作为支出，不二次扣优惠。仍不将未支付或未知交易类型自动扣款。
- **缺失必要资料**：识别资料自动以“待补全”记录进入本机流水列表，显示具体缺失原因，不停在处理记录等待确认。未知金额保持空并显示“金额待补全”，不编造账户、金额或交易日期，不计入余额或收支汇总。缺日期按截图日期排列，保留缺失提示。点击该流水可以补全资料，完成后以真实入账流水替代，不保留第二条待补全记录；资料补全后才按普通流水同步。投影来自持久化截图任务和稳定流水编号，不会被云端同步覆盖。
- **允许重复添加**：每次选图或快捷截图创建独立任务；同图、同订单、同日同商户同金额均可再次自动入账，包括原流水已删除的情况。旧版 `postedOrders` 凭据读取时忽略，不再拦截。仍保留同一任务 UUID 的幂等性，系统重复回调或重试已完成任务不会生成第二笔。
- **旧重复拦截记录**：当前已登录空间启动时，对旧版未入账的识别记录重新校验，符合条件自动入账；有必要字段缺失则自动纳入本机待补全流水，不自动填写未知金额和账户。已入账任务不重放。
- **删除记录**：处理记录可左滑删除，清除该条分析资料和图片，不修改已生成的交易、余额或同步队列，不保存订单拦截凭据；处理中暂不可删除。删除失败保留原记录。
- **失败重试**：识别前持久化稳定 UUID 和图片，网络错误、超时、无权限或模型格式错误保留原任务。处理中意外退出可重新处理。关闭功能后禁止新的外发；已发出的请求不能撤回，但其返回不得自动入账。
- **隐私**：图片只发给当前服务器及已同意配置的 AI；重编码剔除图片元数据，不读取整个相册。失败/待确认最多保留 10 张，每张最多 3 MB，保存在受设备数据保护的本机账本中，成功或忽略后逻辑清理图片。任务回执仍保留交易提取结果和摘要，以识别同一次任务的完成状态。服务端不持久化图片，不记录模型正文和密钥。模型提供方的数据保留仍遵循对应服务政策。
- **同步**：图片和同意不上传财务同步；确认后的普通交易沿用现有队列。任务状态、交易、余额、同步命令一次原子落盘。同步后的临时账户/分类 ID 通过原有 aliases 映射。识别依赖登录与网络，本机确认不必等待同步成功。

## 接口与代码

- `PaymentImageProcessor.swift`：相册和快捷指令共用图片校验、方向修正、最长边 2000 像素 JPEG 重编码。
- `ScreenshotIntent.swift`：图片型后台 `LiveActivityIntent`，持久化任务并提交系统后台上传后立即返回“已开始识别”，不等待 AI，不弹结果对话框或主动打开应用。移除 `LongRunningIntent`，避免其系统进度界面长时间占用灵动岛。快捷指令自己的结束钩子仅表示截图已交付，不代表入账。
- `ScreenshotBackgroundBookkeeping.swift`：用后台 URLSession 从受保护文件上传，网络进程负责请求，后台完成事件唤醒共享应用进程。响应先落盘，再校验原空间、服务器、凭据摘要和同意版本，沿用唯一尾号匹配和原子入账。进程恢复重新接管已有请求，不重传；已入账响应重放不产生第二笔交易，丢失系统任务标记可重试。临时正文及身份快照在结果提交后清理，不保存明文令牌；拒绝重定向并限制响应大小。
- `ScreenshotActivityShared` / `ScreenshotActivityWidget` / `ScreenshotActivityReporter.swift`：共享状态协议、Widget 扩展和实时活动生命周期。紧凑灵动岛左侧显示状态图标，右侧识别时转圈、入账后显示勾，待补全及失败使用对应图标，不显示计时或文字；展开及最小布局同样只使用图标和转圈，不显示业务文字；锁屏保留状态文字，详细原因点击进入处理记录；系统决定药丸旁布局及是否分离圆岛，应用不能指定独立圆岛位置。识别中、已入账、待确认、失败显示在灵动岛及锁屏；终态展示十秒后结束（系统后台执行时间不足或任务取消时可能提前结束），锁屏结果最多保留一分钟。活动超时显示中断，系统未允许实时活动时仍处理记账。状态不包含交易金额、商户或账户；用户点击活动才通过受控链接打开处理记录。不需要推送服务器或 App Group。
- `ScreenshotBookkeeping.swift`：按用户空间保存设置/任务，状态机、白名单匹配、同任务幂等、原子入账及可测试的请求生命周期。
- `ScreenshotBookkeepingView.swift`：设置、系统教程、处理记录及待确认表单。
- `internal/ai/screenshot.go`：认证 + `GetUsable` 配置授权 + 同意版本，5 MB 请求上限，3 MB 图片上限，45 秒模型期限，64 KB 上游响应上限。仅支持 JPEG/PNG 内嵌数据，不读取客户端图片 URL；拒绝跨地址重定向。无工具目录，不调用聊天编排器或记账能力。
- 返回严格 JSON，金额为十进制字符串，日期 `yyyy-MM-dd`、时间 `HH:mm`，与原账本时间协议一致。畸形、未知字段或缺失必需字段失败，业务资料不全强制待确认。模型依然可能识别错误，结构校验和证据字段不构成识别准确性的保证。

## 验证及真机边界

后台上传版新增检查覆盖：进程恢复时保留系统持有的处理任务；上传丢失保存失败原因及图片；迟到错误不覆盖已入账回执；跨空间错误只写原空间。流水首页提供“图片记账待处理”入口，处理记录直接显示未入账原因。系统后台上传真实唤醒及真机灵动岛仍须设备验证，普通 URLProtocol 测试不能代替这些项目。

先前长任务版验证：Debug 模拟器构建通过；专用验证模拟器通过 `--preview --screenshot-activity-preview processing` 成功创建虚构活动并加载 Widget，截图未确认灵动岛可见效果，不视为视觉验收通过。其他虚构状态为 `posted`、`review`、`failed`，预览不会识别真实图片或创建流水。

当前后台上传版验证：Debug 模拟器构建通过，生成元数据 `supportedModes=1`、`openAppWhenRun=false`，已移除长任务及进度上报系统协议，App 内打包 Widget 扩展并启用 `NSSupportsLiveActivities`。现有 441 项检查、截图持久化及网络生命周期（含新增恢复、迟到错误及跨空间错误测试）、分类目录、卡面和卡号测试通过。当前测试没有真实执行系统后台上传唤醒或真实 AI 请求，真机上岛及自动入账仍须验证。

已执行的验证结果以本次交付记录为准。专项测试覆盖精确金额、异常资料、模型输出与图片边界、私有配置越权、旧同意版本、无工具请求、上游重定向拒绝、同图/订单独立重复入账、删流水后重新添加、旧重复拦截恢复、强退恢复、保存失败不改内存、网络超时同任务重试、停用和账号切换期间结果隔离，以及旧 ID 映射。

上线前在真机检查：快捷指令能找到动作并传入图片；背面轻点先截屏且停留原页面；应用未运行时后台启动与实时活动权限；灵动岛状态更新和结束；禁用实时活动仍能记账；点击待确认状态进入处理记录；微信/支付宝实际成功页及详情页识别；实际扣款卡尾号和 AI 分类建议；重复轻点；慢网络超过 30 秒；断网重试；锁屏/解锁与系统中断；实际模型视觉兼容性。模拟器编译、内存上游测试和入口 UI 测试不代表这些真机项目已通过。
