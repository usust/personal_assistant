# 贷款账户实现约定

实现提示词及调研来源见 [贷款账户提示词](../prompts/loan-account.md)。

- 入口是账户类型中的“贷款”，复用 `/finance/accounts`；不使用 Web 遗留但后端未实现的 `/finance/loans`。
- 贷款资料为 `loanPrincipal`、`loanAnnualRate`、`loanMethod`、`loanPeriods`、`loanPaidPeriods`、`loanFirstPaymentDate`、`loanLender`、`loanReceivingAccountId`。年利率使用百分数字符串（0–100、最多四位小数），金额字符串精确到分；收款账户用 0 解除关联。
- `POST /finance/loan-preview` 是认证后的只读试算，不创建账户、流水或写操作审计。试算结果包含计划、下一期和总利息；账户查询只附加摘要 `loanPlan`。
- 还款方式：`annuity` 等额本息、`equal_principal` 等额本金、`interest_only` 每月付息末期还本。每期本金、利息四舍五入到分，末期清偿剩余本金；日期从首次还款日锚定，短月取月末。已还期数决定下一期，不能把日期已过自动算作已还。
- 新贷款默认以计划剩余本金建立负债；未自动增加关联收款账户余额，也不生成收入。已有账户修改条款只改变计划；“剩余本金”单独校准实际欠款，保留快照，存在待确认流水时拒绝校准。计划与账本可能因提前还款或历史录入差异而不同。
- 实际还款沿用流水：本金转账到贷款账户，利息单列支出。计划支持手动分期调息和单期应还额修正，不自动扣账、自动标记已还、接入 LPR、计算罚息手续费或同步银行账单。
- iOS 贷款隐藏信用额度和账单日，支持历史账户补填计划、本机剩余期次还款提醒。Web 在第三栏展示同一组字段及试算，支持同步编辑信用账户设置；提醒配置由 iOS 刷新后排程，Web 本身无后台推送。
- 后端启动 AutoMigrate 增加贷款字段；旧账户零本金表示尚无计划，读取与只修改备注不改变历史欠款。上线需同时更新服务端和客户端。

验收覆盖三种还款方式、零利率、1/480 期、微小金额尾差、闰年与短月、已结清、单字段及多字段 PATCH、显式零值、事务回滚、跨用户关联、历史账户、HTTP 保存回显和双端编译。

## iOS 详情和完整计划

资产列表点击贷款进入详情，非贷款账户保留原编辑入口。详情自动加载账户全部已入账流水，底层每页 500 笔直至结束，完整读取后才展示月度流入／流出汇总；按非空月份倒序分组并可折叠，列表与月份内流水延迟渲染。取消、跨会话和分页失败不发布不完整汇总；不拼凑历史余额和时分。更多菜单支持修改、完整计划、记账可选开关及查询影响后删除。

完整计划页读取账户的权威分期计划，使用 Decimal 汇总本金、利息和本息六项金额；状态与进度来自维护的已还期数，明确标记为计划值。支持全部／已还／待还筛选。详情的剩余本金使用计划摘要；账户列表、分组、总负债及净资产统一使用未还期次的本息合计。账本余额仍独立留存，不因计划已还期数而生成或改写流水。

「已还」按期次倒序显示，最近一期在前；「全部」「待还」维持原期次顺序，仅改变展示顺序，不重排保存的计划。iOS 与 Web 的所有分期卡片（包括调整预览）统一将本金、利息、年利率放在同一行。

详情“记本金还款”入口预选贷款为转入账户，复用真实转账与幂等机制；不把本息总额全部冲减贷款本金，不自动更新已还期数。隐藏账户与独立归档尚无接口，因此不伪造这两个菜单动作。

### iOS 视觉布局

- 详情采用独立概览卡：账户身份、应还金额与日期、双列本金指标、计划入口和期数进度。只有概览与计划入口之间保留一条分隔线，避免每段内容被系统列表拆成单独行。
- 流水月份标题与明细放在同一卡片内；空月份不重复占位，整段时间无记录时只显示一个空状态。不再限制最近三个月或提供逐月加载入口。
- 计划页以两列分别汇总已还／计划剩余，本息、本金、利息使用一致的数字对齐；单期卡片集中显示状态、日期、应还金额、本金利息及该期年利率。未还且仍有本金的期次支持原生向左滑显示「金额」「利率」两个按钮，点击后进入该期表单；不显示总调整按钮或行尾箭头，关闭完整滑动直接触发。
- 两页统一 20 点内容边距、24 点圆角和动态字体。调整表单的期次与日期同一行，预览卡片的本金、利息、年利率同一行，窄屏统一缩放；背景与卡片颜色跟随系统浅色／深色模式。

视觉验收使用 Debug 只读样本，覆盖有流水、空流水、完整计划、深色模式及更大字号；样本截图不作为真实接口联调证据。

## 分期调息与银行账单校准

- `GET /finance/accounts/:id/loan-plan` 返回完整已保存计划，包含 `revision`、`paidPeriods`、`lastPaymentPeriod`，逐期包含 `annualRate`、历史月供设置 `customPayment` 和单期修正标记 `paymentOverridden`。旧贷款没有快照时按原始合同计算；首次确认已还期数或调整时保存完整快照。
- `POST /finance/accounts/:id/loan-adjustment-preview` 只读预览；`POST /finance/accounts/:id/loan-adjustments` 保存。公共字段为 `revision`、`fromPeriod`。`kind: rate` 提交 `annualRate`；`kind: reprice` 提交 `annualRate`、`scope: period`、正金额字符串 `payment`，同时调息并校准本期银行账单。旧 `kind: payment` 单期修正及缺少 kind 的历史请求仍兼容。旧服务端拒绝未知 reprice，需先升级服务端。
- 账单校准先按新利率重算选中期及以后，再保留选中期计划本金，以“银行本期应还额 − 本期本金”校准该期利息；金额不得低于本期本金。校准行标记 `paymentOverridden`、`interestCalibrated`，本息合计必须等于应还额。该入口不表示提前还本，不根据单期金额反推执行利率。
- 等额本金调息保留原本金摊销和末期尾差，后续正常月份利息为期初剩余本金 × 年利率 / 12；等额本息按剩余本金和剩余期数重算。既有自定义月供与账单校准继续保留。日期复用原计划，31 日不会因二月调息而漂移。
- 预览和保存采用同一计算逻辑。保存检查版本并通过 map 原子更新 `loan_schedule_json` 与 `loan_revision`，不会更新原始合同利率、本金、账户余额、流水或已还期数；重复旧版本返回 409，不重复生效。`loan_schedule_json` 使用 longtext，容纳 480 期。
- 已有已还期数或快照的账户锁定原始本金、初始利率、方式、总期数与首次还款日；普通 PATCH 不能绕过历史保护。仍支持已还期数、备注等单字段修改，清零已还期数不解除快照保护。升级前历史账户首次修改会先冻结旧计划。
- iOS 和 Web 均预览所选期次起最多三期并对照原应还额；金额表单提供新年利率与本期应还金额，利率表单仅提供新年利率。切换期次回填对应利率和金额，修改输入即作废预览。已还期次仍可校准，不改实际流水与余额。
- iOS 通知仍依据未还期次和原日期排程，计划提前结清后不对零金额尾期继续提醒。Web 沿用第三栏分层返回，保存锁定关闭；所有金额计算只在服务端完成。

此功能按整期、年利率 / 12 计算，不模拟银行期中按日分段计息；利率与金额由用户依据实际合同或银行计划填写。实现依据及测试要求见提示词第三阶段。服务端需与两端同步更新，启动时 AutoMigrate 增加快照和版本列。

银行规则参考：[工商银行个人贷款合同](https://media.icbc.com.cn/agreement/1109329653548240898.html) 区分按月与按日等额本金计息，具体日数与重定价规则以合同为准。本实现的正常月份采用按月模型，跨调息日当期由已核对的银行账单金额校准；不得宣称可自动复现所有银行的分段日息。回归样例：65 万元、360 期、每期本金 1,805.56 元，第 39 期从 3.3% 调至 3.2%，校准应还 3,376.92 元，第 40—46 期依次为 3,351.12、3,346.30、3,341.49、3,336.67、3,331.86、3,327.04、3,322.23 元。

## 贷款欠款与已还汇总

- 摘要增加 `paidPrincipal`、`paidInterest`、`paidTotal`、`remainingInterest`、`remainingTotal`、`totalPayment`，完整计划与不含 schedule 的账户摘要同源。按 `paidPeriods` 划分已还和未还；本息合计按逐期 payment 求和，兼容银行账单校准与旧单期修正。
- iOS 详情首行展示剩余本金和合同贷款本金，下一行展示剩余欠款（含利息）及已还本息。已还 47/360 期、65 万元等额本金示例的剩余本金为 565,138.68 元。
- 账户列表右侧主金额为剩余本息欠款的负数，下方为全期本息「总贷款」；左侧显示贷款类型及下一期还款倒计时，已过日期仅显示待还日期，不自动认定逾期。
- iOS 账户汇总与后端总览的总负债采用未还本息；净资产同步扣除该金额。未设计划的贷款仍使用账本余额，不计入净资产与归档规则继续生效。全部期次已还后贷款欠款为零，即使未补录历史流水也不再显示原始余额。

账户品牌图标在 iOS 按非透明、非近白的有效图案边界统一等比缩放，保留原配色及内部白色细节；移除中国银行单独放大系数。标准化结果按资源名缓存在有限内存缓存中，不修改共享原始素材。
