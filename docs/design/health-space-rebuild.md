# 健康空间重构：完整实施提示词

请在现有 Personal Assistant iOS 项目中，将健康管理重构为具有个人健康画像、自动能量参考、照片餐食日记和情感化动态反馈的原生健康空间。保留已有账号隔离、网络错误处理、照片外发授权、识别后人工核对、幂等保存和云端健康报告能力。

## 产品意图

普通用户不应先知道自己每天需要多少千卡。入口先展示个人健康概览，再进入饮食记录。界面有趣、有记忆点，但真实健康数据、可理解的操作和阅读舒适性优先。不要创造没有依据的“健康总分”，不要把没有读取到的数据显示成零，也不要把少吃或超量变成羞辱、惩罚或奖励。

## 页面与交互

1. 健康概览：在“我的 → 健康管理”展示身体画像。以原生圆角内容面、人体/生命力主题视觉和少量环绕数据构成主视觉；清晰呈现身高、体重、年龄，以及身体、活动、心率/呼吸、睡眠等指标。提供 Apple 健康连接、资料补齐、饮食记录、同步与报告入口。导航栏使用居中 inline 小标题。
2. Apple 健康：使用 HealthKit 公开只读 API，按功能请求所需类型，涵盖身高、体重、出生日期、生理性别、BMI、体脂、瘦体重、步数、步行跑步距离、活动与静息能量、锻炼、站立、楼层、心率、静息心率、HRV、血氧、呼吸频率、睡眠、运动、饮水、膳食能量和心肺适能等支持项。累计量、最近测量和睡眠区间分别处理，标明实际数据日期。用户选择部分权限也能使用。授权完成不等于所有数据可读，空结果只显示“暂无数据”，不能武断声称权限被拒。
3. 每日能量参考：默认估算成人维持体重所需能量，使用 Mifflin–St Jeor 基础代谢公式与用户确认的活动系数。身高、体重、年龄与公式所需生理参数优先取可读取数据，缺失时允许手动补齐；活动水平不从单日步数推断。展示计算依据和必要适用条件。未成年人、超出支持年龄、孕哺期或需要专业营养指导的情况不套用通用公式。允许保留专业指导的手动目标。用户点击采用后保存结果，不能默默覆盖已有目标。
4. 饮食页：日期选择在上方；主操作“拍照记一餐”用原生液态玻璃按钮、明确可见的相机图标和轻盈透明质感。不得把亮青色图标放在同色实心按钮上。支持拍照、相册和手动记录，保留显式外发同意与食物克数、热量的核对流程。
5. 餐食卡片：每餐显示真实照片缩略图、餐次、主要食物和估算千卡，展开查看明细/备注并删除。仅在用户确认保存餐食后保留本机压缩缩略图；最长边 480 像素、JPEG 上限 120 KB、去除 EXIF，原图不持久化。按服务器与账号隔离，删除餐食时清理缩略图。历史无图记录使用餐具占位，不伪造食物照片。照片保存在本机，换设备不能保证显示，相关说明放在需要做决策的位置。
6. 动态结论：在餐食列表之后，用一个圆润可爱的“能量小伙伴”配合单色比例刻度表达已记录摄入与每日参考值。区分未记录、未设置参考值、参考值内、接近参考值和超过参考值；超出 100% 必须保留真实百分比/差值，不截断成“刚好达标”。不要用大段总结文字替代视觉表达，也不能只靠表情或颜色让人猜。点开可看完整数值和依据，VoiceOver 读出比较结果。未记录不等于没吃，动画不催促跳餐或额外运动补偿。

## 视觉方案

形态先于配色：身体画像用可读数值与图标；摄入比较使用单一比例刻度而非多个不同量纲的环形图；食物身份由照片承担。采用系统字体，核心数值使用 rounded 字形。浅色背景跟随系统 grouped 背景，深色跟随系统背景，内容面保持实底。品牌能量色：浅色 #287F88、深色 #46969F；主文字跟随系统 primary，辅助文字 secondary。辅助装饰只用于主体小伙伴，避免每张卡片都有渐变和闪烁。

布局：

```text
健康管理                        饮食记录
┌ 身体画像 · 真实身高/体重/年龄 ┐ ┌ 日期                 ┐
│      柔和人体主题视觉        │ │ 每日参考值 / 调整    │
└─────────────────────────┘ └─────────────────────┘
[连接 Apple 健康] [完善资料]     [ 透明相机 · 拍照记一餐 ]
[身体 / 活动 / 睡眠 / 生命体征]  [缩略图 · 午餐 · 约 xxx 千卡]
[相关指标及实际采样日期]         [缩略图 · 晚餐 · 约 xxx 千卡]
[饮食记录 →]                   [能量小伙伴 · 比例刻度 · 明细]
[同步与报告 →]
```

检查：不用健康总分的巨大数字作为主视觉，改用身体画像；不把各指标强行做成同一种进度环；不把玻璃铺到全部业务内容上。视觉大胆之处集中在身体画像和小伙伴，列表与表单保持安静。

## 工程与验收

- 只使用当前 Xcode SDK 支持的公开 API，遵守项目 AGENTS.md，新增/修改函数和重要回调提供中文参数、返回值、副作用注释。
- 扩展健康信息留在本机；现有云端五类日汇总与报告保持单独的上传/AI 授权流程。不将个人健康画像暗中发送给餐食识别服务。
- 保留旧接口和旧餐食数据兼容性，账号/服务器切换不能串数据。请求取消、部分授权、读取失败、无图、缩略图写入失败、云端保存结果未知都有明确可恢复路径。
- 支持深浅色、动态字体、VoiceOver、减少动态效果与降低透明度；减少动态效果时展示静态状态，不使用持续弹跳。
- 验证热量公式、边界值、缺失信息、特殊人群、比例超限、睡眠区间合并以及本地缩略图路径隔离。执行可用编译与测试；真机 HealthKit 授权、相机和视觉检查受环境限制时如实记录。
