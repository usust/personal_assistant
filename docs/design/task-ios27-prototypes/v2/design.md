## 单入口信息架构

原 App 全局 Tab 保持今日、任务、财务、健康、助手、用户、设置，由原生系统决定溢出展示。图中首页按现有截图显示今日、任务、财务、健康、More，不增加任务模块独立 Tab。

任务根页：居中小标题“任务”，清单入口、更多、新增；搜索；“结构／安排”是内容视图切换；清单与状态筛选。
结构：展开任务树，查看主任务与下级关系。
安排：按日期分组可执行叶子，不重复显示其主任务；保留完整或可展开的来源路径。
详情、表单、归属选择、清单管理均从任务页进入；子页面隐藏全局 Tab，底部只放当前业务操作。
返回根页保留视图、筛选、搜索、展开节点和滚动位置。清单管理关闭后恢复任务页上下文。

## 核心流程

创建：任务页 + → 名称 → 清单／父任务 → 一次完成或量化进度 → 优先级／日期 → 保存。选择父任务后清单受其约束；改清单时清空不兼容父级并重新选择。创建子任务继承归属，日期和优先级不静默继承。
执行：安排视图 → 叶子详情 → 勾选一次任务或量化 +步长 → 原位更新 → 主任务重新汇总。
调整：任务详情／行更多／多选工具栏 → 调整归属 → 清单与父任务 → 影响预览 → 提交 → 更新结构。
整理：完成后可留在已完成范围；归档用于收起，不等同于完成；恢复归档不会重置进度。

## 细节功能规则

| 功能 | 交互与约束 |
| --- | --- |
| 搜索 | 匹配名称与子任务；结果展示归属路径；点击进入详情，清除搜索恢复树状态 |
| 筛选 | 清单、进行中／已完成／已归档；高优先级等附加条件放更多筛选，不堆常驻控件 |
| 排序 | 手动、截止、优先级；只有结构视图且同级手动排序允许拖动；按日期、搜索中使用显式归属操作 |
| 任务树 | 行首展开箭头与完成／进度控件分开，点击正文打开详情；深层不无限缩窄，进入父级详情继续下钻 |
| 归属选择 | 清单＋父任务；“无父任务（顶级）”用于提升，不更改执行方式；支持搜索和路径消歧 |
| 循环与权限 | 自身及后代排除；只展示本人数据；提交时重新校验循环、目标可用性和清单一致性 |
| 同清单重挂 | 后代随节点保留关系；更换父任务后原、新祖先进度重新汇总；不重置日期、备注和进度 |
| 跨清单迁移 | 整棵子树同步更新清单，原子提交；这是待补能力。现接口拒绝有后代节点直接改清单，不伪装成功 |
| 确认强度 | 带后代／跨清单／批量变更展示原位置、新位置和影响数量；普通单叶同清单移动可直接提交并简短反馈 |
| 多选 | 父节点与后代同时选中时归一为最高选中节点，数量明确“选中节点／包含后代”；避免重复移动或删除 |
| 批量 | 调整归属、归档、删除；在提交前验证全部目标，不采用静默部分成功；原子批量接口尚未实现 |
| 进度 | 一次任务可映射为总量1、步长1、单位次；量化任务使用已有总量、已完成、步长、单位；单位不绑定层级 |
| 主任务 | 有下级时展示汇总，无直接加进度或强制完成按钮；空主任务显示“未拆分”，不显示100% |
| 汇总口径 | 建议默认各执行叶子比例等权平均，避免20页＋1次直接相加；需跨端统一并评估历史数据，不能本轮直接改公式 |
| 一次完成 | 未完成切至满量，取消完成回到0；修改必须由服务端明确保存，并可反馈失败 |
| 量化增加 | 点击+步长立即提交一次，成功才更新；提交中禁用重复写；末步不足步长时截至总量；满量后禁用+ |
| 量化减少 | 最低0；允许两位小数；总量与步长须大于0；保存校验沿用业务约束 |
| 执行转汇总 | 给已有进度的叶子加下级时，需明确进度转由下级汇总的影响，不能悄悄丢弃历史含义 |
| 时间 | 开始、截止可空；选择日期后才有可选时间；截止不得早于开始；当前是本地日历数据，无通知承诺 |
| 安排归组 | 已逾期优先；今天含开始日／截止日为今天及跨今天的有效执行任务；未来按下一个相关日期分组；无日期单列“未安排” |
| 完成与归档 | 分开表达；已归档只读、允许恢复；现实现归档父级不自动归档子级，v2默认沿用且子级仍可独立展示 |
| 删除 | 独立破坏性确认，显示“删除任务及N个子任务”；清单删除显示范围；当前无可恢复快照，不展示虚假撤销 |
| 移动撤销 | 待补能力；需可恢复的原父级、清单、排序及版本，不以现有事件日志冒充撤销快照 |
| 失败与并发 | 保存失败保留草稿，移动失败保留原树；目标被删时回选择页；写结果不明先刷新，避免重复创建／进度请求 |
| 清单外观 | 名称备注紧邻图标左对齐；新建居中预览、编辑不显示预览；颜色17常用色＋系统颜色盘，严格六列三行；SF Symbols跨端键 |
| 辅助功能 | VoiceOver区分展开、完成、调整归属；文字可放大、路径可换行；减少动态效果时浮动标签和层级变化弱化动画 |
| AI入口 | 复用原 App 助手模块能力，不额外建任务AI Tab；批量原子拆分等尚未实现，不在原型中暗示已有 |

## 现有实现检查与差距

检查文件：apps/iOS/PersonalAssistant/ContentView.swift、Features/TasksView.swift、Core/Models.swift；backend/internal/task/service/tasks.go；docs/task-management.md。

已有：单任务入口、清单、名称备注、优先级、起止日时、层级模型、量化进度、排序、归档恢复、级联删除、服务端重挂白名单与循环／清单校验。
iOS 尚缺直接更换父任务入口，编辑清单也被禁用。后端同清单重挂可以保留后代。
待设计实现：结构展开视图、安排视图、显式归属选择、批量原子操作、整树跨清单迁移、统一的完成显示与一次完成捷径、可撤销快照。
特别问题：当前 Models.swift 汇总将所有叶子总量直接相加，不同单位显示工作量；空主任务在顶层计算时返回100%。v2提出修正，不代表代码已修复。
PATCH 必须继续使用白名单校验 map，只写本次变更字段，支持0、false、空串、parentId:null。
图片是独立场景示例：图二演示任务原型已有两个下级，图一演示其仍为叶子；不应作为同一时刻数据快照。清单数量示意，不构成精确数据契约。

## iOS 27 Liquid Glass视觉验收

- [iOS 27官方更新说明](https://support.apple.com/en-gb/149076)：可读性改进，系统设置支持从清透至着色调节；不在模块里另造玻璃透明度设置。
- [Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials)：玻璃承载控件与导航，克制使用自定义玻璃。
- [采用Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)：优先系统布局与控件，避免内容／操作层混淆。
- 常规页面navigationTitle与inline居中标题；透明导航背景由系统管理，按钮使用原生圆形／胶囊。
- 底部TabView／Toolbar采用系统材质、滚动边缘和安全区行为，不手画阴影模拟原生玻璃。
- 玻璃体现底层内容透射、边缘折射、柔和投影和自适应对比；不使用大范围彩色壁纸使表单看起来玻璃化。
- 任务列表、备注、表单、进度条是普通系统背景内容层，不叠多层玻璃。
- 主操作使用系统着色玻璃；次要控件随系统材质。禁止把所有白色胶囊都当作必须加玻璃的对象。
- 明暗模式、系统透明度、减少透明度、增强对比度、减少动态效果、Dynamic Type均需实机验收。
- 静态AI图无法证明实时折射、交互形变、触感或系统透明度完全一致；严格动态验收必须用目标SDK公开API构建并在iOS27运行。本轮未实现或运行原生原型。
