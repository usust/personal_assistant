# 健康管理

## 补充完善后的实施提示词

在现有个人助手系统中新增“健康管理”模块，打通 iOS HealthKit → 已认证后端 → AI 健康报告 → iOS/Web 展示的完整流程。复用现有登录、用户隔离、AI 配置和数据库迁移机制，不改动用户已有代码或数据。

1. iOS 增加健康入口，明确说明读取和上传范围，经用户同意后仅申请 HealthKit 读取权限。首版支持步数、活动能量、步行/跑步距离、静息心率、体重，读取最近 30 个自然日（含今天，今天截至同步时刻），统一单位并携带设备时区。无记录或未授权统一显示缺失，禁止伪造零值或声称已获得全部读取权限。
2. 后端提供有认证的批量同步、总览、报告生成和清除接口。数据严格归属当前登录用户；用户不能通过请求指定归属。按用户和日期幂等覆盖日快照，保留未提交日期；零值及缺失值准确覆盖。限制批量大小、正文、日期和指标范围，事务保证完整写入。
3. AI 分析前要求用户选择其有权限使用的配置并明确同意将健康日汇总发送至该服务商。独立调用无工具权限的模型，仅分析本人已同步数据。输出数据覆盖、引用日期和数值的趋势观察、生活方式建议、数据局限及适当的就医提示，不诊断、不处方、不虚构病史或未采集指标。保存报告及原始日汇总快照；模型失败提供重试入口，不伪造成功报告。
4. Web 新增导航、每日指标表和报告历史。详情、分析表单及清除确认遵守统一 WorkspacePanel 第三栏规范；移动端适配已有层级切换。iOS 提供授权同步、模型选择、报告查看和清除操作。退出或切换用户不得将旧读取结果上传给新账号。
5. 健康数据只用于用户请求的管理和分析，不在业务日志中打印，不自动外发给 AI。支持删除个人服务端汇总及报告，说明删除不影响 HealthKit 原始数据、重新同步会重新上传。
6. 完成迁移、文档、后端隔离及幂等集成测试、前端构建和 iOS 编译；明确真实设备授权和真实模型联调尚需验证的边界。

## 当前实现

首版采用用户主动同步和主动生成报告，避免未经同意持续读取或外发。HealthKit 不提供读取权限是否被拒绝的判断，因此“授权请求完成”不等于“所有指标已授权”。参考 [Apple HealthKit 授权说明](https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data)。

| 字段 | 单位 | 日汇总口径 |
| --- | --- | --- |
| steps | 步 | HealthKit cumulativeSum |
| active_energy | 千卡 | 活动能量 cumulativeSum，不包含基础代谢 |
| distance | 米 | 步行/跑步距离 cumulativeSum |
| resting_heart_rate | 次/分钟 | HealthKit 静息心率 discreteAverage，不是全天普通心率 |
| weight | 千克 | 当日测量 discreteAverage，不沿用之前日期的体重 |

iOS 读取 30 个自然日（含今天，今天截至同步时刻），采用本机时区，服务端总览取最近 30 个有日快照的日期。历史日期可能因停用而陈旧，AI 提示词包含当前日期并要求说明陈旧数据。空指标上传后清除该日期旧指标；这不代表撤销权限会自动删除所有历史数据，用户可以主动清除。同步失败不缓存健康数据、不后台重试，用户可安全重新同步。单项 HealthKit `errorNoData` 视为缺失，继续读取其他指标；整批全空时不上传，以免把无权限误报成成功。全部撤销权限后需要清除历史数据时，使用“删除服务器健康数据及报告”。

同一用户同一日期仅保留一份汇总，重复请求不叠加数值，数据库记录 ID 保持稳定。建议固定由一台 iPhone 同步；多台设备采用最后一次成功提交的日快照，不合并相互重叠的数据源。HealthKit 统计值可能与健康 App 按来源优先级展示的数值不同。跨时区旅行后重新同步按当前设备时区划分日期。

报告只向所选服务商发送日汇总，无任务/财务/用户管理工具执行能力；服务端记录模型配置 ID、时间与分析快照。报告按纯文本展示，避免执行模型返回的 HTML。总览返回最近 20 份报告；更早报告保留在数据库中，首版不提供分页查看。

## API

均须 Bearer 登录，统一使用 `{ "data": ... }` 信封，健康业务路径与进程存活检查 `/api/health` 分开。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health-management` | 最近 30 个记录日及 20 份报告 |
| POST | `/api/health-management/sync` | `days` 数组，1–31 天；每批原子写入 |
| POST | `/api/health-management/reports` | `config_id` 与 `consent: true`，最长 90 秒 |
| DELETE | `/api/health-management` | 删除本人所有健康日汇总及报告 |

同步示例：

```json
{
  "days": [{
    "date": "2026-09-26",
    "timezone": "Asia/Shanghai",
    "steps": 6500,
    "active_energy": 320,
    "distance": 4100,
    "resting_heart_rate": 62,
    "weight": null
  }]
}
```

数值上限用于防止错误单位和异常负载，不是医学阈值。日期必须位于最近两年且不能在未来，日期不得重复；正文上限 64 KiB。健康同步是**完整日快照**协议，某日未提供的指标清空；它不是 PATCH。一般 PATCH 仍必须遵守仓库的字段 map 更新规则。

启动迁移创建 `health_days`（用户/日期唯一索引）和 `health_reports`。不迁移或删除其他业务表。部署仍使用现有数据库与 AI 配置；健康表应受与其他私有业务数据相同的数据库访问和备份控制。

## 使用与验收

1. 启动更新后的后端，等待自动迁移；部署更新后的 Web。
2. iOS 工程已包含 HealthKit entitlement 和读取用途说明。真机签名需在 Apple 开发者账号对应 App ID 开启 HealthKit，并更新 provisioning profile。
3. 登录 iPhone 客户端 → 健康（或今日/我的中的健康同步入口）→ 同步到服务器 → 同意并开始同步。分别验证全部授权、部分授权、全部拒绝以及手机暂无记录。
4. 重复同步，Web 应只有每日期一条记录；在健康 App 修改/删除某日记录后重同步，确认相应指标变更。没有读取到的值应为 `—`，明确的零值仍显示 `0`。
5. 选择已配置的 AI 服务，同意外发后生成报告；分别验证配置不可用、网络中断、模型失败以及成功后的两端报告查看。
6. 用另一账号登录，不能查看或删除前一账号数据。读取期间退出/切换服务器，结果不得上传给新会话。
7. 清除健康数据并刷新，两端应为空；手机原始记录保持不变。Web 的取消确认不得删除，分析提交中第三栏不能关闭。

自动化验证覆盖后端真实路由、SQLite 迁移、认证、用户隔离、重放、零值/缺失、批量校验、模型配置权限、外发同意、无工具调用、模型错误和清除；不连接真实 HealthKit 或外部 AI。iOS 模拟器构建只能证明编译通过，真机读取及真实服务商结果仍须按上述步骤验收。

## 首版边界

不包含后台自动同步、HealthKit 增量锚点、原始样本留存、睡眠分期、多设备来源优先级、医学评分或自动诊断。后续扩展睡眠需要处理跨午夜区间、重叠来源和分期去重；不能简单累加样本。当前没有定时分析或用户级频率限额，生成一次报告会调用一次用户选择的模型服务。

## iOS 同步问题修复

- “今日”和“我的”均增加“健康管理 · 同步到服务器”入口。健康页顶部显示当前账号和服务器，点击同步时明确说明授权范围。下拉刷新只加载服务器数据，不上传手机数据。
- 旧实现会因某天没有体重/静息心率等数据返回 `errorNoData` 而中断整个批次；现仅将这种错误转换为缺失，锁屏等真实查询错误仍中止。参见 [Apple errorNoData 文档](https://developer.apple.com/documentation/healthkit/hkerror/code/errornodata)。
- 包含今天的数据，按公历和设备时区计算日边界，并处理夏令时。当天数据未结束，不能直接与完整历史日比较。
- 同步展示读取、上传、核对进度，验证服务端 `synced` 回执，显示有效数据天数及服务器最近接收时间。全部为空不发上传请求；上传成功但刷新失败时保留成功说明。
- AI 配置加载失败不再阻止健康记录展示；服务器返回 404 时提示更新后端或检查地址。
- 新增 11 项 iOS 回归断言（总计 58 项）覆盖无样本、真实错误、当天、夏令时、零值、全空不上传、实际请求端点与回执。真实 iPhone 的安装版本、读取权限和服务器连接仍需在设备上验收。
