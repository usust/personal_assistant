# v4 实施方案

2026-10-05。用户明确采用 docs/design/task-ios27-prototypes/v4 的设计，覆盖此前清单中心方向与空 main 100% 的旧决策。v4 两张静态图已查看；继承的 v3 文件缺失，只按 v4 明确内容实施，不声称继承未见规则。参考目录为用户未提交文件，不修改或提交。

## 实施范围

- 唯一任务 Tab 的根显示清单与搜索、归档入口；清单页面用连续列表面显示可展开任务树。推入页面隐藏全局 Tab，不新增模块 Tab。
- 主任务以稳定图标键表示文件夹；具体任务用进度环/完成标识且不能新建下级。历史具体任务已有下级仍保留容器展示，不迁移或丢弃数据。
- 主任务只汇总实际具体叶任务数量，5/10+1/1=6/11、54.5%；空主任务0/0显示“暂无任务”，嵌套空主任务不贡献旧配置。混合单位不标为某一种单位。
- 主/具体详情区分：图标与路径、数值/细进度条、下级或日期/进度配置、备注；系统底部工具栏放新建下级或进度增减。危险操作保留确认与共享写保护。
- 编辑复用浮动标签，不加大预览；清单、父主任务直接选择，父候选排除自身及后代；主图标选择为六列搜索目录，只改草稿，保存后持久，取消不写。
- 清单颜色/图标既定规则保留。系统字体、语义颜色、原生导航/工具栏玻璃；内容为普通可读背景。浅深与辅助字号适配，不照搬图像中比例误差。

## 必要共享依赖与兼容

新增后端Task.icon、白名单map更新与AI字段说明；旧JSON缺icon回退文件夹，未知已保存键显示回退但不覆写。旧客户端省略icon不覆盖，新功能需配套后端；不静默本地伪持久化。不部署服务或迁移真实数据。

新建/实质改变parentId只允许main父级；历史未变父关系的其他字段PATCH继续可用。有下级不可主动转具体任务，历史subtask容器可显式改main，禁止隐式数据迁移。

清单归属修改使用原PATCH，在现有用户锁事务内统一修改主节点与后代list_id；验证目标清单、归属、父级和循环后map写入，失败全部回滚。换清单草稿清除旧父，提交parentId:null或有效新父，不新增独立移动流程。Web只同步共享汇总与合法父候选等必要逻辑，不做Web视觉重构。

删除沿用确认后整树cascade。归档是否级联因v3缺失已向用户询问；未确认前保留当前单节点归档/恢复，不改变其他任务状态。现有AI来源、无任务通知、失败保护和云身份隔离保留。
